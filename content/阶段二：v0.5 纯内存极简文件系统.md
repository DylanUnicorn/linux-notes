# 阶段二：v0.5 — 纯内存极简文件系统

> [!info] 实验目标
> 利用 initrd.img 机制，从零构建一个极简文件系统，使内核启动后**直接在内存中获得一个 Shell**，不挂载任何硬盘。在 GRUB 中增加一个启动入口进行测试。

---

## 1. 核心工具：BusyBox

BusyBox 被称为嵌入式 Linux 的"瑞士军刀"，能把几百个常用命令（`ls`, `cd`, `sh`, `mount` 等）压缩成**一个极小的可执行文件**。

> [!important] 必须使用静态编译版
> 静态版 BusyBox 不依赖系统的动态链接库（`.so`），在极简内存环境中才能正常运行。

---

## 2. 操作步骤

### 2.1 安装 BusyBox 并创建目录骨架

```bash
# 安装静态版 busybox
sudo apt update
sudo apt install busybox-static

# 创建 v0.5 根文件系统工作区
cd ~
mkdir my_rootfs_v0.5
cd my_rootfs_v0.5

# 创建 Linux 标准目录骨架
mkdir -p bin sbin etc proc sys dev usr/bin usr/sbin
```

### 2.2 部署 BusyBox

```bash
# 将 busybox 复制到 bin 目录
cp /bin/busybox ./bin/
```

> [!warning] `--install -s .` 可能静默失败
> BusyBox 自带的 `--install` 命令在某些版本下会因路径解析问题而静默失败，不生成任何软链接。

**推荐使用手动循环创建软链接的方法：**

```bash
cd ~/my_rootfs_v0.5/bin

# 查看 busybox 内置的所有命令
./busybox --list

# 用 for 循环为每个命令创建软链接
for cmd in $(./busybox --list); do ln -s busybox $cmd; done

# 验证：应该能看到大量指向 busybox 的软链接
ls -l | head -n 15

cd ~/my_rootfs_v0.5
```

> [!tip] 备选方案：下载官方纯静态版
> 如果系统自带的 busybox 不是纯静态的，可以直接下载官方编译好的版本：
> ```bash
> wget https://busybox.net/downloads/binaries/1.35.0-x86_64-linux-musl/busybox -O bin/busybox
> chmod +x bin/busybox
> ```

### 2.3 编写 /init 脚本

```bash
cat << 'EOF' > init
#!/bin/sh

# 告诉系统去这些文件夹里找命令
export PATH=/bin:/sbin:/usr/bin:/usr/sbin

# 挂载虚拟文件系统
mount -t proc proc /proc
mount -t sysfs sysfs /sys
mount -t devtmpfs devtmpfs /dev

echo "======================================="
echo "  SUCCESS! Welcome to My Linux v0.5!"
echo "  Running entirely in RAM (initramfs)"
echo "  All commands should work now!"
echo "======================================="

# 将 shell 直接绑定到控制台，避免因输入输出流丢失而崩溃
exec /bin/sh < /dev/console > /dev/console 2>&1
EOF

chmod 777 init
```

### 2.4 打包生成 initrd.img

按照 Linux 2.6+ 内核要求的格式（`cpio` + `gzip`）打包：

```bash
# 在 my_rootfs_v0.5 目录下执行
find . -print0 | cpio --null -ov --format=newc | gzip -9 > ../my_initrd_v0.5.img

# 复制到 /boot 目录
sudo cp ../my_initrd_v0.5.img /boot/
```

### 2.5 配置 GRUB 启动入口

**获取当前内核路径：**
```bash
ls /boot/vmlinuz-$(uname -r)
# 输出示例：/boot/vmlinuz-5.15.0-100-generic
```

**编辑自定义 GRUB 文件：**
```bash
sudo nano /etc/grub.d/40_custom
```

**在文件末尾追加：**
```
menuentry "Test My Minimal Rootfs v0.5" {
    linux /boot/vmlinuz-5.15.0-xxx-generic
    initrd /boot/my_initrd_v0.5.img
}
```

> [!warning] 注意事项
> - 把 `vmlinuz-5.15.0-xxx-generic` **替换为你自己的真实内核版本号**
> - 不要添加 `root=...` 参数（因为我们不挂载硬盘）
> - 不要添加 `quiet` 参数（方便查看启动日志排错）

**更新 GRUB 并重启：**
```bash
sudo update-grub
sudo reboot
```

### 2.6 测试

1. 重启时狂按 `ESC` 或 `Shift` 呼出 GRUB 菜单
2. 选择 **"Test My Minimal Rootfs v0.5"**
3. 等待内核启动日志滚完
4. 看到欢迎语和 `#` 提示符即为成功

**验证命令：**
```bash
ls          # 查看目录结构
pwd         # 查看当前路径
df -h       # 查看挂载情况（应该只有内存文件系统，无硬盘）
```

## 3. 踩坑记录与排错

### 3.1 Kernel Panic: No working init found

**现象**：内核成功加载了 initrd.img，但报错找不到可运行的 `/init`

**可能原因及解决方案：**

| 原因 | 解决方案 |
|------|---------|
| 打包时包含了外层目录，路径变成 `/my_rootfs_v0.5/init` | 确保在工作目录**内部**执行 `find . -print0 \| cpio ...` |
| `/bin/sh` 是坏掉的软链接 | 直接复制 `cp bin/busybox bin/sh` |
| Windows 换行符 `\r` 干扰 | 执行 `sed -i 's/\r$//' init` |

**验证打包内容是否正确：**
```bash
lsinitramfs /boot/my_initrd_v0.5.img | grep -E "^init$|^bin/sh$"
# 应输出 init 和 bin/sh 两行
```

### 3.2 Shell 启动但所有命令 not found

**现象**：看到欢迎语和 `#` 提示符，但 `ls`、`mount` 等命令报 `not found`

**原因**：BusyBox 的软链接没有正确生成 + 缺少 `PATH` 环境变量

**解决方案：**
1. 用 `for` 循环手动创建软链接（见 2.2 节）
2. 在 `init` 脚本中添加 `export PATH=/bin:/sbin:/usr/bin:/usr/sbin`

### 3.3 控制台绑定问题导致 Shell 瞬间退出

**现象**：内核加载 initrd 后，Shell 因找不到终端（TTY）而直接退出，触发 Kernel Panic

**解决方案**：在 `exec /bin/sh` 时绑定控制台：
```bash
exec /bin/sh < /dev/console > /dev/console 2>&1
```

## 4. 关键原理

### 4.1 为什么不需要 run-init / switch_root？

v0.5 的目标是**整个文件系统运行在内存中，不调用硬盘资源**。
- `run-init` / `switch_root` 的作用是将根目录从内存切换到物理硬盘
- 我们的 `/init` 最后一行是 `exec /bin/sh`，直接"截胡"了这个切换过程
- 系统永远停留在内存文件系统中

### 4.2 打包格式

```
find . -print0 | cpio --null -ov --format=newc | gzip -9 > output.img
```

| 参数 | 含义 |
|------|------|
| `find . -print0` | 列出当前目录所有文件，用 NULL 字符分隔（处理特殊文件名） |
| `cpio --null -ov --format=newc` | 以 newc 格式（Linux 2.6+ 标准）创建 cpio 归档 |
| `gzip -9` | 最高压缩率压缩 |

### 4.3 v0.5 启动流程

```
GRUB 选择 v0.5 启动项
    → 加载 vmlinuz（Linux 内核）
    → 加载 my_initrd_v0.5.img
    → 内核解压 cpio 归档到内存（ramfs）
    → 执行 /init 脚本
        → 挂载虚拟文件系统（proc, sysfs, devtmpfs）
        → 启动 BusyBox 提供的 Shell
    → 用户在纯内存环境中获得 # 提示符
```
