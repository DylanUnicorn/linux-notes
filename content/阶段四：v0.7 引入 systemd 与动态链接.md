# 阶段四：v0.7 — 引入 systemd 与动态链接 Bash

> [!info] 实验目标
> 在 v0.5 纯内存系统的基础上，引入现代 Linux 的进程管理器 `systemd` 作为 PID 1，并用 systemd 的服务配置管理动态链接版的 `/bin/bash`，实现 **Bash 退出后自动重启**（`Restart=always`）。

---

## 1. 核心概念

### 1.1 为什么需要 systemd？

| 对比项 | v0.5（BusyBox Shell） | v0.7（systemd 管理） |
|--------|----------------------|---------------------|
| PID 1 | `/init` 脚本自身 | `systemd` |
| Shell 退出后 | **Kernel Panic**（系统崩溃） | systemd 自动重启 Shell |
| 服务管理 | 无 | 可通过 `.service` 文件声明式管理 |
| 进程监控 | 无 | 崩溃检测 + 自动重启 |

### 1.2 静态链接 vs 动态链接

| 类型 | 代表 | 特点 |
|------|------|------|
| 静态链接 | BusyBox（v0.5） | 所有代码打包在一个文件中，不依赖外部 `.so` 库 |
| 动态链接 | `/bin/bash`、`systemd` | 运行时需要加载外部共享库（`.so` 文件） |

> [!important] v0.7 的核心难点
> systemd 和标准 bash 都是**动态链接**的，极度依赖宿主机的 `.so` 动态库文件。必须把它们及所有依赖库完整迁移到内存文件系统中。

---

## 2. 操作步骤

### 2.1 创建工作区与依赖拷贝脚本

```bash
# 基于 v0.5 复制一份 v0.7 工作区
cd ~
cp -r my_rootfs_v0.5 my_rootfs_v0.7
cd my_rootfs_v0.7

# 创建存放构建脚本的临时目录
mkdir -p build_tools
```

**编写自动依赖拷贝脚本 `cp_libs.sh`：**

```bash
cat << 'EOF' > build_tools/cp_libs.sh
#!/bin/bash
# 自动通过 ldd 查找并拷贝依赖库的脚本

TARGET_DIR=$(pwd)
BIN_PATH=$1

if [ -z "$BIN_PATH" ] || [ ! -f "$BIN_PATH" ]; then
    echo "Usage: $0 <absolute_path_to_binary>"
    exit 1
fi

echo "Copying dependencies for $BIN_PATH..."

# 提取依赖并循环复制
ldd "$BIN_PATH" | awk '{print $3}' | grep "^/" | while read lib; do
    lib_dir=$(dirname "$lib")
    mkdir -p "${TARGET_DIR}${lib_dir}"
    if [ ! -f "${TARGET_DIR}${lib}" ]; then
        cp "$lib" "${TARGET_DIR}${lib}"
        echo "Copied: $lib"
    fi
done

# 单独处理动态链接器（ld-linux）
ld_loader=$(ldd "$BIN_PATH" | grep -o '/lib.*\.[0-9]' | head -n 1)
if [ -n "$ld_loader" ] && [ ! -f "${TARGET_DIR}${ld_loader}" ]; then
    lib_dir=$(dirname "$ld_loader")
    mkdir -p "${TARGET_DIR}${lib_dir}"
    cp "$ld_loader" "${TARGET_DIR}${ld_loader}"
    echo "Copied loader: $ld_loader"
fi
EOF

chmod +x build_tools/cp_libs.sh
```

### 2.2 引入 bash 与 systemd

```bash
# 拷贝标准 bash 及其依赖
cp /bin/bash ./bin/bash
./build_tools/cp_libs.sh /bin/bash

# 拷贝 systemd 及其依赖
mkdir -p ./lib/systemd
cp /lib/systemd/systemd ./lib/systemd/systemd
./build_tools/cp_libs.sh /lib/systemd/systemd

# 确保 lib64 目录存在（链接器需要）
mkdir -p lib64
cp -r /lib64/* ./lib64/ 2>/dev/null || true
```

### 2.3 编写 bash.service（systemd 服务配置）

```bash
mkdir -p etc/systemd/system

cat << 'EOF' > etc/systemd/system/bash.service
[Unit]
Description=Interactive Bash Shell managed by systemd
DefaultDependencies=no

[Service]
Type=simple
ExecStart=/bin/bash
StandardInput=tty-force
StandardOutput=inherit
StandardError=inherit
TTYPath=/dev/console
# 核心：退出后立刻重启
Restart=always
RestartSec=1

[Install]
WantedBy=default.target
EOF
```

### 2.4 创建 default.target

> [!warning] systemd 的后缀强迫症
> `.target` 类型的软链接**必须指向另一个 `.target` 结尾的文件**。
> 如果直接 `ln -s bash.service default.target`，systemd 会报：
> `symlink target "bash.service" has incompatible suffix, rejecting.`
> 然后直接冻结（`Freezing execution`）。

**正确做法：创建真正的 `.target` 配置文件：**

```bash
cat << 'EOF' > etc/systemd/system/default.target
[Unit]
Description=My Minimal Default Target
Requires=bash.service
DefaultDependencies=no
AllowIsolate=yes
EOF
```

### 2.5 将 /init 指向 systemd

```bash
# 移除旧的 init 脚本
rm init

# 让内核启动的第一个进程变为 systemd
ln -s lib/systemd/systemd init

# 建立基础文件防止 systemd 报错
echo "v0.7-systemd" > etc/hostname
touch etc/os-release
```

### 2.6 打包、GRUB 配置与测试

```bash
find . -print0 | cpio --null -ov --format=newc | gzip -9 > ../my_initrd_v0.7.img
sudo cp ../my_initrd_v0.7.img /boot/
```

GRUB 启动项（`/etc/grub.d/40_custom`）：
```
menuentry "Test My Minimal Rootfs v0.7 (systemd bash)" {
    linux /boot/vmlinuz-$(uname -r) rw init=/init
    initrd /boot/my_initrd_v0.7.img
}
```

> [!tip] 注意 `rw` 参数
> 必须加上 `rw`（读写模式），否则 systemd 会因只读文件系统报错。

## 3. 踩坑记录：动态链接器的"幽灵文件"

### 3.1 Kernel Panic: error -2 (ENOENT)

**现象**：内核报 `Requested init /init failed (error -2)` — 文件看似存在但无法执行

**根因**：`/lib64/ld-linux-x86-64.so.2` 是一个**死链接（Broken Symlink）**。`cp` 命令只拷贝了软链接本身而非真实文件。

**排错方法 — "特洛伊木马"调试法：**

1. 用 BusyBox 的静态 Shell 作为 `/init` 先成功启动
2. 在内存系统内部手动执行 `/bin/bash`，观察具体报错
3. 用 `ls -l /lib64/ld-linux-x86-64.so.2` 检查是否为死链接（输出中箭头 `->` 指向不存在的路径）
4. 用加载器直接审问：`/lib64/ld-linux-x86-64.so.2 --list /bin/bash`

**终极修复：暴力硬拷贝**

```bash
cd ~/my_rootfs_v0.7

# 彻底删除残留的软链接
rm -f ./lib64/ld-linux-x86-64.so.2
rm -f ./lib/x86_64-linux-gnu/ld-linux-x86-64.so.2

# 确保目录存在
mkdir -p ./lib64
mkdir -p ./lib/x86_64-linux-gnu

# 从宿主机绝对路径硬拷贝真实文件（不走软链接）
cp /lib/x86_64-linux-gnu/ld-linux-x86-64.so.2 ./lib64/
cp /lib/x86_64-linux-gnu/ld-linux-x86-64.so.2 ./lib/x86_64-linux-gnu/

# 赋予执行权限
chmod +x ./lib64/ld-linux-x86-64.so.2
chmod +x ./lib/x86_64-linux-gnu/ld-linux-x86-64.so.2
```

> [!tip] 核心教训
> 动态链接器（`ld-linux`）本身必须是具有**可执行权限的实体二进制文件**。如果它是坏链接或缺少 `+x` 权限，内核报的是 `error -2`（找不到文件），而非权限不足，极易误导排查方向。

### 3.2 Bash 启动时的正常警告

```
bash: cannot set terminal process group (-1): Inappropriate ioctl for device
bash: no job control in this shell
```

**这是正常现象**，不影响功能。Bash 尝试接管终端（TTY）的控制权实现任务控制（`Ctrl+Z`、后台运行等），但在嵌套 Shell 或 initramfs 环境下，它拿不到完整的终端控制权。

## 4. 关键原理

### 4.1 systemd 服务配置结构

```ini
[Unit]              # 声明单元的元数据和依赖关系
Description=...     # 人类可读的描述
DefaultDependencies=no  # 去除默认依赖（网络、日志等）

[Service]           # 定义服务的运行方式
Type=simple         # 主进程类型
ExecStart=...       # 启动命令
Restart=always      # 退出后自动重启
RestartSec=1        # 重启间隔

[Install]           # 何时启用此服务
WantedBy=...        # 被哪个 target 拉起
```

### 4.2 v0.7 验证测试

- 输入 `exit` 退出 Shell → Shell **瞬间复活**（systemd 的 `Restart=always` 生效）
- `echo $$` → 当前 Bash 的 PID **不是 1**（PID 1 是 systemd）
