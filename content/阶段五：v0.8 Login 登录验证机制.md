# 阶段五：v0.8 — Login 登录验证机制

> [!info] 实验目标
> 在 v0.7 的 systemd 基础上，引入 `login` 程序实现用户身份验证：
> 1. 开机后出现 `login:` 提示，而非直接进入 Shell
> 2. 输入正确用户名/密码后才能获得 Shell
> 3. 输入错误凭据时拒绝登录
> 4. 退出 Shell 后回到登录界面（而非系统崩溃）

---

## 1. 核心概念

### 1.1 标准 Linux 登录流程

```
systemd (PID 1)
  → 启动终端守护进程 (getty) / login 程序
    → 显示 "login:" 提示
    → 用户输入用户名/密码
    → 验证 /etc/passwd + /etc/shadow
    → 通过 → 启动用户对应的 Shell（如 /bin/bash）
    → 失败 → 提示 "Login incorrect"，重新提示输入
```

### 1.2 PAM 避坑策略

| 方案 | 依赖 | 适用场景 |
|------|------|---------|
| 原生 `/bin/login` | 依赖 `libpam.so` + `/etc/pam.d/` 大量配置 + `/lib/.../security/` 模块 | 完整 Linux 发行版 |
| **BusyBox `login`** | 仅依赖 `/etc/passwd` + `/etc/shadow`，不依赖 PAM | **极简 initramfs（我们的选择）** |

> [!tip] BusyBox 的 login 是最佳平替
> 完全不依赖 PAM 认证框架，只认最原始的 passwd/shadow 文件，非常适合我们的极简系统。

---

## 2. 操作步骤

### 2.1 创建身份验证文件

```bash
cd ~/my_rootfs_v0.7

# /etc/passwd — 指定 root 的默认 Shell 为动态版 bash
echo "root:x:0:0:root:/root:/bin/bash" > etc/passwd

# /etc/group
echo "root:x:0:" > etc/group

# /etc/shadow — 第二个字段为空代表不需要密码（初步测试用）
echo "root::19000:0:99999:7:::" > etc/shadow

# shadow 文件极其敏感，必须限制权限
chmod 600 etc/shadow

# 创建 root 用户的家目录
mkdir -p root
```

### 2.2 启用 BusyBox 的 login

```bash
# 建立软链接，让 /bin/login 指向 BusyBox
ln -sf busybox ./bin/login
```

### 2.3 编写 console-login.service

```bash
cat << 'EOF' > etc/systemd/system/console-login.service
[Unit]
Description=Console Login Prompt
DefaultDependencies=no
After=systemd-user-sessions.service

[Service]
Type=simple
# 不再直接启动 bash，而是启动 login
ExecStart=-/bin/login
StandardInput=tty-force
StandardOutput=inherit
StandardError=inherit
TTYPath=/dev/console
Restart=always
RestartSec=1
# 忽略 login 退出时的某些状态码
SuccessExitStatus=0 1

[Install]
WantedBy=default.target
EOF
```

> [!note] `ExecStart=-/bin/login` 中的 `-` 号
> 这是 systemd 语法，表示如果命令非正常退出，不要报错，直接重启。

### 2.4 更新 default.target

```bash
# 删除 v0.7 的旧目标
rm etc/systemd/system/default.target

cat << 'EOF' > etc/systemd/system/default.target
[Unit]
Description=Login Target
Requires=console-login.service
DefaultDependencies=no
AllowIsolate=yes
EOF
```

### 2.5 删除旧的 bash.service

> [!warning] 不删除 bash.service 会导致进程抢占控制台
> 如果 `bash.service` 和 `console-login.service` 同时存在，两者会竞争 `/dev/console` 的控制权，出现：
> - 键盘输入被 bash 抢走，login 收不到
> - 用户输入 `root` 后被 bash 当命令执行，报 `bash: root: command not found`
> - 界面极度卡顿，两个进程交替刷屏

```bash
rm etc/systemd/system/bash.service
```

## 3. 加入密码验证

### 3.1 为什么不能在虚拟机里直接 `passwd`？

> [!warning] initramfs 是纯内存文件系统
> 在虚拟机里用 `passwd` 修改的密码仅存在于当前内存中，重启后会从 initrd.img 重新解压，一切恢复原样。
> 
> 正确做法：**在宿主机上预先加密密码，写入 shadow 文件后再打包**。

### 3.2 生成并烧录密码

```bash
cd ~/my_rootfs_v0.7

# 使用 openssl 生成 SHA-512 密码哈希（-6 = SHA-512）
# 将 "123456" 替换为你想设置的密码
HASH=$(openssl passwd -6 "123456")

# 确认生成的密文（以 $6$ 开头的长字符串）
echo $HASH

# 将密文注入 shadow 文件
echo "root:${HASH}:19000:0:99999:7:::" > etc/shadow

# 验证写入
cat etc/shadow
```

### 3.3 shadow 文件字段说明

```
root:$6$salt$hash:19000:0:99999:7:::
 │      │         │    │   │    │
 │      │         │    │   │    └─ 保留字段
 │      │         │    │   └────── 密码过期前警告天数
 │      │         │    └────────── 密码最短使用天数
 │      │         └─────────────── 最后修改日期（距1970年的天数）
 │      └───────────────────────── 加密后的密码哈希
 └──────────────────────────────── 用户名
```

## 4. 打包与测试

```bash
find . -print0 | cpio --null -ov --format=newc | gzip -9 > ../my_initrd_v0.8.img
sudo cp ../my_initrd_v0.8.img /boot/
```

GRUB 启动项：
```
menuentry "Test My Minimal Rootfs v0.8 (login prompt)" {
    linux /boot/vmlinuz-$(uname -r) rw init=/init
    initrd /boot/my_initrd_v0.8.img
}
```

### 4.1 验证项目

| 测试 | 操作 | 预期结果 |
|------|------|---------|
| 登录提示 | 开机后观察 | 显示 `v0.7-systemd login:` |
| 正确登录 | 输入 `root` + 密码 | 进入 `bash-5.1#` |
| 错误登录 | 输入错误用户名或密码 | 提示 `Login incorrect` |
| 退出恢复 | 在 Shell 中输入 `exit` | 回到 `login:` 提示符（不会 Kernel Panic） |

> [!note] 输入密码时无星号显示
> 这是 Linux 的标准行为，密码输入过程中屏幕不会有任何字符反馈，盲敲即可。
