# 阶段六：v0.9 — 完整 systemd 运行环境

> [!info] 实验目标
> 补全 systemd 的基础设施，消除 `var-run-bad` 等污染警告，引入 `systemctl` 和 `journalctl` 工具以及日志服务 `systemd-journald`，使系统具备现代 Linux 的服务管理与日志追溯能力。

---

## 1. 当前问题诊断

v0.8 的 systemd 虽然能正常工作，但启动日志中有一行关键警告：

```
systemd[1]: System is tainted: var-run-bad
```

### 1.1 "光杆司令" systemd 的不足

| 缺失项 | 影响 |
|--------|------|
| `/run` 目录不存在 | `var-run-bad` 污染警告，进程间通信（IPC）异常 |
| `/var/run` 未指向 `/run` | systemd 启动时的强制检查不通过 |
| 无 `systemd-journald` | 日志无处保存，排错困难 |
| 无 `systemctl` | 无法在系统内管理服务 |
| 无 `journalctl` | 无法查看启动日志和历史记录 |

---

## 2. 操作步骤

### 2.1 修复底层目录骨架

```bash
cd ~/my_rootfs_v0.7

# 创建系统运行时必须的基础目录
mkdir -p run tmp var/log

# 建立 systemd 强依赖的软链接（解决 var-run-bad）
# /var/run 必须是指向 /run 的软链接
ln -snf ../run var/run
```

> [!note] `ln -snf` 参数说明
> - `-s`：创建软链接
> - `-n`：如果目标已存在且是目录，不进入该目录
> - `-f`：强制覆盖已存在的文件/链接

### 2.2 引入 systemd 的"左膀右臂"

使用之前的 `cp_libs.sh` 脚本自动处理依赖：

```bash
# systemctl — 系统服务管理工具
cp /bin/systemctl ./bin/
./build_tools/cp_libs.sh /bin/systemctl

# journalctl — 日志查询工具
cp /bin/journalctl ./bin/
./build_tools/cp_libs.sh /bin/journalctl

# systemd-journald — 日志记录后台守护进程
cp /lib/systemd/systemd-journald ./lib/systemd/
./build_tools/cp_libs.sh /lib/systemd/systemd-journald
```

### 2.3 编写日志服务配置

```bash
cat << 'EOF' > etc/systemd/system/systemd-journald.service
[Unit]
Description=Journal Service
DefaultDependencies=no

[Service]
ExecStart=/lib/systemd/systemd-journald
Restart=always
EOF
```

### 2.4 升级 default.target

同时拉起日志服务和登录服务，并确保日志先于登录启动：

```bash
cat << 'EOF' > etc/systemd/system/default.target
[Unit]
Description=Complete Systemd Target
# 同时要求日志服务和登录服务
Requires=systemd-journald.service console-login.service
# 日志先于登录启动
After=systemd-journald.service
DefaultDependencies=no
AllowIsolate=yes
EOF
```

## 4. 验证命令

登录系统后执行以下命令验证 v0.9 的功能完整性：

### 4.1 systemctl status — 查看进程树

```bash
systemctl status
```

**预期输出**：一棵完整的进程树，systemd 作为 PID 1，下挂 `systemd-journald` 和 `login` → `bash` 进程链。

### 4.2 journalctl -b — 查看启动日志

```bash
journalctl -b
```

**预期输出**：从内核启动到 systemd 初始化的完整详细日志。`var-run-bad` 的污染警告**不再出现**。

### 4.3 日志服务验证

```bash
systemctl status systemd-journald
```

**预期输出**：显示 `active (running)` 状态。

## 5. systemd 核心工具速查

| 命令 | 功能 |
|------|------|
| `systemctl status` | 查看系统总体状态与进程树 |
| `systemctl status <service>` | 查看指定服务的运行状态 |
| `systemctl start <service>` | 启动服务 |
| `systemctl stop <service>` | 停止服务 |
| `systemctl restart <service>` | 重启服务 |
| `systemctl list-units` | 列出所有已加载的单元 |
| `journalctl -b` | 查看本次启动的完整日志 |
| `journalctl -f` | 实时跟踪日志输出 |
| `journalctl -u <service>` | 查看指定服务的日志 |

## 6. v0.5 → v0.9 架构演进总结

```
v0.5  BusyBox Shell (PID 1) ─── 静态链接，无管理
        │
v0.7  systemd (PID 1) ─── bash.service ─── Bash
        │                   Restart=always
        │
v0.8  systemd (PID 1) ─── console-login.service ─── login → Bash
        │                   密码验证
        │
v0.9  systemd (PID 1) ─┬─ systemd-journald.service ─── 日志守护
                        └─ console-login.service ─── login → Bash
                            systemctl / journalctl 可用
```
