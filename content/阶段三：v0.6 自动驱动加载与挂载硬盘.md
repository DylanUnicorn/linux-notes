# 阶段三：v0.6 — 自动加载驱动与挂载物理硬盘

> [!info] 实验目标
> 在 v0.5 的基础上进一步完善文件系统：
> 1. 通过 mdev（轻量级 udevd 平替）**自动识别硬件并加载驱动**
> 2. **挂载物理硬盘**上原有的 Ubuntu 系统，获得访问标准系统文件的能力

---

## 1. v0.6 核心概念

### 1.1 为什么 v0.5 看不到硬盘？

在 v0.5 的纯内存环境中，内核是个"瞎子"：
- 没有加载 VMware 硬盘控制器的驱动（SCSI/SATA `.ko` 模块）
- 没有加载 `ext4` 文件系统的驱动
- 因此 `/dev/sda3` 设备节点根本不存在，挂载操作静默失败

### 1.2 两大核心任务

| 任务 | 说明 | 工具 |
|------|------|------|
| **自动设备识别** | 动态识别硬件并加载对应驱动 | BusyBox 的 `mdev`（udevd 的轻量级平替） |
| **挂载真实硬盘** | 将物理硬盘上的 Ubuntu 系统挂载到内存系统中 | `mount` 命令 |

### 1.3 mdev vs udevd

| 对比项  | udevd               | mdev              |
| ---- | ------------------- | ----------------- |
| 来源   | systemd 组件          | BusyBox 内置        |
| 依赖   | 庞大，需要完整的 systemd 环境 | 极轻量，适合 initramfs  |
| 功能   | 完整的热插拔管理            | 基础的设备识别与驱动加载      |
| 适用场景 | 完整的 Linux 发行版       | 嵌入式系统 / initramfs |

## 2. 操作步骤

### 2.1 确认硬盘分区名称

在正常 Ubuntu 系统中执行：

```bash
lsblk
```

找到 `MOUNTPOINTS` 列显示为 `/`（根目录）的行，记下设备名。

> [!example] 本次实验结果
> `sda3` — 容量 69.5G，挂载点为 `/`
> 完整路径：`/dev/sda3`

### 2.2 搬运官方内核驱动模块

从阶段一解压的官方 initrd.img 中复制精简版驱动库：

```bash
cd ~/my_rootfs_v0.5

# 创建驱动目录并拷贝官方最小依赖集
mkdir -p usr/lib/modules
cp -r ~/initrd_study/extracted_files/main/usr/lib/modules/* ./usr/lib/modules/

# 创建软链接，确保系统从 /lib 也能找到驱动
mkdir -p lib
ln -s ../usr/lib/modules ./lib/modules
```

> [!important] 软链接路径陷阱
> 必须使用 `../usr/lib/modules` 而**不是** `./usr/lib/modules`
>
> **原因**：软链接的相对路径是**相对于链接文件本身所在位置**来解析的，而非相对于执行命令时的当前目录。
>
> ```
> 错误：ln -s ./usr/lib/modules ./lib/modules
>   → 系统在 lib/ 下找 ./usr/lib/modules
>   → 实际寻找：lib/usr/lib/modules  ← 不存在！
>
> 正确：ln -s ../usr/lib/modules ./lib/modules
>   → 系统在 lib/ 下先 ../ 退到上级
>   → 实际寻找：usr/lib/modules  ← 正确！
> ```
>
> **铁律**：制作系统镜像时，严格使用相对路径构建内部软链接，绝不使用绝对路径。

### 2.3 配置 mdev 与用户文件

创建基础的用户档案（让系统识别 `root`）：

```bash
mkdir -p etc

# 建立最基础的用户和组文件
echo "root:x:0:0:root:/root:/bin/sh" > etc/passwd
echo "root:x:0:" > etc/group

# 配置 mdev 自动加载规则
# 含义：对任何带 MODALIAS 属性的硬件，自动执行 modprobe 加载对应驱动
echo '$MODALIAS=.* 0:0 660 @modprobe "$MODALIAS"' > etc/mdev.conf
```

> [!warning] 缺少 /etc/passwd 和 /etc/group 的后果
> mdev 规则中引用 `root:root` 时，如果系统没有用户文件，会报错：
> `unknown user/group 'root:root'`
> 导致 mdev 罢工，所有驱动都无法加载。

### 2.4 编写 v0.6 版 /init 脚本

```bash
cat << 'EOF' > init
#!/bin/sh

export PATH=/bin:/sbin:/usr/bin:/usr/sbin

mount -t proc proc /proc
mount -t sysfs sysfs /sys
mount -t devtmpfs devtmpfs /dev

echo "======================================="
echo "  Welcome to My Linux v0.6!"
echo "  Auto-loading hardware drivers..."
echo "======================================="

# 1. 启动 mdev 硬件守护程序
echo /sbin/mdev > /proc/sys/kernel/hotplug
mdev -s

# 2. 核心机制：自动加载所需驱动（平替 udevd 功能）
# 遍历内核通过 sysfs 吐出的所有硬件 MODALIAS
# 让 modprobe 自动匹配并加载对应的 .ko 驱动模块
for alias_file in $(find /sys -name modalias); do
    modprobe $(cat $alias_file) 2>/dev/null
done

# 给内核3秒钟处理驱动并生成 /dev/sda 硬盘节点
sleep 3

echo "--- Current Block Devices ---"
ls -l /dev/sda*
echo "-----------------------------"

# 3. 挂载真实物理硬盘
mkdir -p /mnt/real_disk
echo "Attempting to mount /dev/sda3..."
mount /dev/sda3 /mnt/real_disk

# 验证是否挂载成功
if [ -d "/mnt/real_disk/etc" ]; then
    echo ">>>> SUCCESS: Real disk is fully mounted! <<<<"
else
    echo ">>>> FAILED: Disk not found. <<<<"
fi

exec /bin/sh < /dev/console > /dev/console 2>&1
EOF

chmod 777 init
```

### 2.5 打包与 GRUB 配置

```bash
# 打包成 v0.6 镜像（因包含驱动文件，体积较大，属正常现象）
find . -print0 | cpio --null -ov --format=newc | gzip -9 > ../my_initrd_v0.6.img

# 复制到 /boot
sudo cp ../my_initrd_v0.6.img /boot/
```

**更新 GRUB 配置**（将 v0.5 改为 v0.6）：

```bash
sudo nano /etc/grub.d/40_custom
```

修改 initrd 行：
```
menuentry "Test My Minimal Rootfs v0.6" {
    linux /boot/vmlinuz-5.15.0-xxx-generic
    initrd /boot/my_initrd_v0.6.img
}
```

```bash
sudo update-grub
sudo reboot
```

重启进入 v0.6 启动项后：

## 3. 自动驱动加载原理详解

### 3.1 MODALIAS 机制

```
硬件设备 → 内核识别 → 在 /sys 下生成 modalias 文件
    → modalias 文件包含硬件身份码（如 "pci:v00008086d..."）
    → modprobe 根据身份码在 modules.alias 中查找对应的 .ko 驱动
    → 自动加载匹配的驱动模块
```

### 3.2 脚本中的驱动加载流程

```bash
# 第一步：注册 mdev 为内核的热插拔处理器
echo /sbin/mdev > /proc/sys/kernel/hotplug
# → 之后每有新设备出现，内核会自动调用 mdev

# 第二步：mdev -s 扫描现有设备
mdev -s
# → 遍历 /sys/dev 创建对应的 /dev 设备节点

# 第三步：遍历所有 modalias 强制加载驱动（冷插拔补充）
for alias_file in $(find /sys -name modalias); do
    modprobe $(cat $alias_file) 2>/dev/null
done
# → mdev -s 有时只创建节点不加载驱动
# → 这个循环确保所有硬件的驱动都被加载
```

### 3.3 关键驱动类型

| 驱动类型 | 作用 | 示例 |
|----------|------|------|
| SCSI/SATA 控制器驱动 | 让内核"看见"硬盘硬件 | `mptspi.ko`, `sd_mod.ko` |
| 文件系统驱动 | 让内核"读懂"硬盘上的数据格式 | `ext4.ko` |
| 块设备层驱动 | 基础的块设备 I/O 支持 | `scsi_mod.ko` |

## 4. v0.6 启动流程

```
GRUB 选择 v0.6 启动项
    → 加载 vmlinuz + my_initrd_v0.6.img
    → 内核解压到内存
    → 执行 /init
        → 挂载虚拟文件系统（proc, sysfs, devtmpfs）
        → 注册 mdev 为热插拔处理器
        → mdev -s 扫描硬件，创建设备节点
        → 遍历 sysfs modalias，加载所有匹配驱动
        → /dev/sda3 设备节点出现
        → mount /dev/sda3 /mnt/real_disk
    → 用户在内存系统中获得 Shell
    → 可通过 /mnt/real_disk 访问原 Ubuntu 系统的全部文件
```

## 5. 踩坑记录

### 5.1 挂载后目录为空

**现象**：`mount` 不报错但 `ls /mnt/real_disk` 为空

**原因**：缺少硬盘控制器驱动和文件系统驱动，`/dev/sda3` 设备节点未生成，`mount` 静默失败

**解决**：从官方 initrd 中复制驱动模块 + 实现 modalias 遍历加载

### 5.2 mdev 报 unknown user/group

**现象**：启动日志出现 `unknown user/group 'root:root'`

**原因**：极简系统缺少 `/etc/passwd` 和 `/etc/group`

**解决**：
```bash
echo "root:x:0:0:root:/root:/bin/sh" > etc/passwd
echo "root:x:0:" > etc/group
```

并将 mdev 规则中的 `root:root` 改为 UID/GID 数字 `0:0`
