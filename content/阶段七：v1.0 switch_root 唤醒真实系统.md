# 阶段七：v1.0 — switch_root 唤醒真实操作系统

> [!info] 实验目标
> 将极简内存系统（initramfs）改造为真正的**引导程序**：在内存中完成硬件侦测与驱动加载后，通过 `switch_root` 将根目录切换到物理硬盘，把控制权移交给硬盘上完整的 Ubuntu 系统——复现标准 Linux 的完整启动过程。

---

## 1. 核心概念：initramfs 的终极使命

在真实的 Linux 发行版中，`initramfs` 并不是终点，而是一个**跳板**。它的终极使命是"自我牺牲"：

```
initramfs 启动（纯内存）
  → 侦察硬件，加载驱动（类似 v0.6）
  → 找到并挂载物理根分区
  → switch_root：踢开内存文件系统，切换到物理硬盘
  → 执行硬盘上的 /sbin/init（systemd）
  → 完整的 Ubuntu 桌面启动
```

### 1.1 switch_root 的工作原理

| 步骤 | 操作 |
|------|------|
| 1 | 清空当前 initramfs 占用的内存 |
| 2 | 将根目录 `/` 切换到指定的物理硬盘挂载点 |
| 3 | 在新的根目录下执行指定的 init 程序（通常是 `/sbin/init`） |
| 4 | 新 init 接管 PID 1，原 initramfs 彻底消失 |

> [!important] switch_root vs chroot
> - `chroot`：仅改变进程视角的根目录，原文件系统仍在
> - `switch_root`：**彻底释放 initramfs 内存**并切换根，是内核级的根目录替换

## 3. 操作步骤

### 3.1 编写终极 /init 脚本

```bash
cd ~/my_rootfs_v0.7

# 删除指向 systemd 的旧 init
rm init

cat << 'EOF' > init
#!/bin/sh

# 1. 基础环境初始化（v0.5 技术）
export PATH=/sbin:/usr/sbin:/bin:/usr/bin
mount -t proc proc /proc
mount -t sysfs sysfs /sys
mount -t devtmpfs devtmpfs /dev

echo "================================================="
echo "  [ Initramfs v1.0 ] The Grand Unification"
echo "  Booting system and looking for real hardware..."
echo "================================================="

# 2. 硬件侦测与驱动加载（v0.6 技术）
echo /sbin/mdev > /proc/sys/kernel/hotplug
mdev -s
for alias_file in $(find /sys -name modalias); do
    modprobe $(cat $alias_file) 2>/dev/null
done

# 3. 等待物理硬盘设备出现
mkdir -p /mnt/root

echo "Waiting for physical disk /dev/sda3 to appear..."
while [ ! -b /dev/sda3 ]; do
    sleep 0.5
done

echo "Disk found! Mounting real root filesystem..."
mount /dev/sda3 /mnt/root

# 4. 平移虚拟文件系统到新根目录（交接准备）
mount --move /sys /mnt/root/sys
mount --move /proc /mnt/root/proc
mount --move /dev /mnt/root/dev

# 5. 终极魔法：switch_root
echo "================================================="
echo "  Mission Accomplished! Handing over to REAL OS"
echo "  Executing switch_root..."
echo "================================================="

exec switch_root /mnt/root /sbin/init

# 如果走到这里，说明 switch_root 失败
echo "PANIC: switch_root failed!"
exec /bin/sh
EOF

chmod 777 init
```

### 3.2 脚本关键步骤详解

#### 等待硬盘设备（防止启动竞争）
```bash
while [ ! -b /dev/sda3 ]; do
    sleep 0.5
done
```
- `-b` 检测是否为块设备文件
- 驱动加载需要时间，循环等待避免在设备节点创建前就尝试挂载

#### 平移虚拟文件系统
```bash
mount --move /sys /mnt/root/sys
mount --move /proc /mnt/root/proc
mount --move /dev /mnt/root/dev
```
- `--move`：将挂载点无缝迁移到新位置
- 硬盘上的真实 systemd 需要这些虚拟文件系统已经就绪
- 如果不平移，switch_root 后 systemd 会找不到 `/dev`、`/proc`、`/sys`

#### switch_root 执行
```bash
exec switch_root /mnt/root /sbin/init
```
- `exec`：替换当前进程（重要：不能 fork 子进程来做）
- `/mnt/root`：新的根目录（物理硬盘）
- `/sbin/init`：新根目录下要执行的程序（硬盘上的 systemd）

### 3.3 打包与 GRUB 配置

```bash
find . -print0 | cpio --null -ov --format=newc | gzip -9 > ../my_initrd_v1.0.img
sudo cp ../my_initrd_v1.0.img /boot/
```

GRUB 启动项：
```
menuentry "The Grand Finale v1.0 (Boot to Real Ubuntu)" {
    linux /boot/vmlinuz-$(uname -r) rw init=/init
    initrd /boot/my_initrd_v1.0.img
}
```

```bash
sudo update-grub
sudo reboot
```

## 5. 踩坑记录

### 5.1 VMware 虚拟网卡导致启动缓慢

**现象**：启动日志出现大量红色报错：
```
e1000 0000:02:01.0 ens33: Detected Tx Unit Hang
A start job is running for Network Manager Wait Online (no limit)
```

**原因**：
- `e1000` 是 VMware 默认的老旧虚拟网卡驱动
- 我们的 `mdev` 加载驱动后通过 `switch_root` 交接给真实 Ubuntu 的 `udev`，这种暴力切换导致虚拟网卡驱动状态异常
- `NetworkManager-wait-online` 服务死等网络连通，阻塞启动

**解决方案 A — 更换虚拟网卡（推荐，治本）：**
1. 彻底关闭虚拟机
2. 找到虚拟机目录下的 `.vmx` 配置文件
3. 搜索 `ethernet0.virtualDev`
4. 将 `"e1000"` 改为 `"vmxnet3"`（VMware 原生高性能半虚拟化网卡）
5. 保存后重新启动

**解决方案 B — 禁用等待服务（治标）：**
```bash
sudo systemctl disable NetworkManager-wait-online.service
sudo systemctl mask NetworkManager-wait-online.service
```
